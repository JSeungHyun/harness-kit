# 관문 — 작업 종료 보고

> 상태: **설계안**

보고 직전에 **매번** 돈다. 계획이 있으면 그 마지막 태스크가 이 스킬을 부르고, 없으면 보고가 곧 관문이다.

## 절차

1. **코드를 바꿨으면 `/ponytail-review`** — 과설계만 본다. 지적마다 걷어내거나, 남기는 이유를 한 줄 적는다. 걷어냈으면 2 를 그 뒤에 돈다
2. **완료 증거** — 작업 종류별로. 없으면 없다고, 왜 없는지 적는다

   | 작업 | 증거 |
   |---|---|
   | 코드 변경 | `node .harness/tools/verify.mjs` — ⛔ exit 0 이 아니면 보고하지 말고 고친다 |
   | 운영 데이터 · 설정 | 실행·확인 쿼리와 전/후 결과 |
   | 기록 변경 | `node .harness/tools/graph-find.mjs --check` — exit 0 |
   | 조사 · 측정 | 정답 라벨 n건 대조 + 검증한 범위 |

3. **보고 한 세트**
   1. 작업 파일 목록 — 생성/수정/삭제, 전체 경로
   2. 기록 — 그래프(요구 → 용어·파일·함정·기각한 대안, `.claude/rules/graph.md` — ⛔ 이 저장소의 지식만, 3절 첫째 문) · 묻지 않고 정한 가정(decisions 1절, 그리고 `node .harness/tools/decision-check.mjs`) · 반복 실패(`node .harness/tools/lesson-append.mjs`, 그리고 `node .harness/tools/lesson-promote.mjs`). 설계 용어를 구현 이름과 맞췄나 본다. ⛔ 기록의 두 장치:
      - **남길 게 없으면 그 판단을 한 줄로** 밝힌다 — 침묵을 불가능하게 만든다
      - 기능을 바꿔 기존 기록이 **낡았으면 그 자리에서 고친다**(그래프는 `supersedes`). 새 기록 추가로 갈음하지 않는다 — **다음 세션의 나는 그 불일치를 사실로 믿는다**. 기준: 「이 기록을 그대로 믿고 작업하면 틀리나」
   3. 완료 증거 — 2 의 출력 그대로. 「통과했다」로 줄이지 않는다
   4. 못 한 것 · 막힌 것 — 그래프에 `⏸` 로 기록한다
4. **브랜치를 마무리하는 보고(merge·PR 직전)면** `/security-review` 1회 → `finishing-a-development-branch`

## ⛔ 하지 않는 것

| ⛔ | 왜 |
|---|---|
| 증거 없이 「끝났다」 | 종료코드·러너 요약은 테스트 0개를 통과시킨다 |
| ponytail-review 통과를 「동작이 맞다」로 읽기 | 과설계만 본다. 정확성은 완료 증거가 맡는다 |
| ponytail 모드를 켜고 작업 | superpowers 의 설계·질문 단계와 충돌한다. 리뷰만 부른다 |
| `/security-review` 를 보고마다 | 브랜치를 마무리할 때 한 번이다 |
| 파일 목록만 보고하고 기록을 건너뛰기 | 둘은 한 세트다 — 다음 세션은 기록만 본다 |
