# 그래프 — 요구 → 용어 · 파일 · 함정

> 상태: **설계안** · 저장소 `.harness/graph/requests.jsonl` — ⛔ 자동 로드되지 않는다. 조회로만 읽어서 무한히 쌓여도 세션 비용이 0이다

같은 것을 두 번 조사하지 않고, 사용자의 말과 코드의 이름 사이에 다리를 놓는다. 값은 `terms`(현업 용어 → 실체)와 `note`(함정)에 있다 — 파일 목록만 쌓으면 git 의 열등한 사본이다.

## 1. 요구가 들어오면 그래프부터

```bash
node .harness/tools/graph-find.mjs <어근…>        # 어근을 짧게, 여러 개 — 부분일치라 조사·접미사가 붙으면 놓친다
node .harness/tools/graph-find.mjs --with <파일>   # 그 파일을 고칠 때 같이 움직이는 파일
node .harness/tools/graph-find.mjs --open          # 하다 만 것(⏸) 전부
```

⛔ 이 조회를 건너뛰지 않는다. 빈손이면 새 영역이다 — 평소대로 코드를 탐색한다. 걸린 것이 답이라는 뜻은 아니다 — 답하지 않으면 그렇다고 말하고 코드로 간다.

**코드 탐색은 세 경우에만** — 기록에 답이 있으면 그대로 옮겨 답한다. 코드를 다시 파는 것은 ①기록에 그 물음의 답이 없다 ②사용자가 부족하다 했다 ③더 보라 했다 — 셋뿐이다. `⚠️ 미확정` 이 없는 항목을 「확인차」 다시 보지 않는다 — 기록을 안 믿으면 기록 비용만 남는다. 단, 새 원천이 기존 기록과 다른 값을 말하면 그때는 다시 본다. 절차 질문에는 `정본: ` 기록을 옮긴다.

## 2. 사용자가 쓴 말이 0건이면 — 알아낸 그 턴에 배운다

```bash
node .harness/tools/graph-alias.mjs <사용자가 쓴 말> "<시스템에서 무엇인가>" [--file 경로]… [--note 함정]
```

⛔ **키는 사용자의 말, 값은 시스템의 실체.** 공식 용어를 키로 적으면 다음에도 못 찾는다. ⛔ 알아내기 전에 적지 않는다 — 다음 세션이 추측을 사실로 믿는다. 조사·띄어쓰기 변형은 적지 않는다(질의 쪽 토크나이저가 만든다).

## 3. 작업이 끝나면 — 파일 목록 보고와 한 세트로 (`final-gate` 의 기록 단계)

```bash
node .harness/tools/graph-append.mjs <<'EOF'
{"req":"<사용자 요구 한 줄>",
 "terms":{"<현업 용어>":"<시스템에서 무엇인가 — 테이블·URL·컬럼·서비스>"},
 "files":["<실제로 만진 파일>"],
 "note":"<다음 사람이 알아야 할 함정 한 줄 · 기각한 대안 한 줄>"}
EOF
```

- `terms` 는 객체로 — 배열이면 해석이 사라진다. `files` 에 줄번호를 붙이지 않는다. 남길 게 없으면 그 판단을 보고에 한 줄로
- **기록 단위는 「이 용어들이 같은 질문에서 함께 필요한가」** — 함께면 주제 기록 1건, 갈리면 2~3건. 광역 사전 1건에 몰아넣으면 그 기록이 적중을 독점하고, 용어 1개짜리로 쪼개면 `req` 가 빈약해 정확일치를 못 받는다
- 커밋에서 만든 기록은 `terms` 를 채워야 값이 있다 — 커밋 제목만 넣으면 0 이다
- ⛔ **개인 식별자(사번·이름·연락처·계정)와 비밀값을 적지 않는다** — 공유 모드에서는 그대로 커밋된다. 사람은 역할로, 이슈는 번호 없이 요지로

## 4. 판단 규칙 — 빈도순 — 피해는 ④가 가장 크다(거짓이 사실로 유통된다)

1. ⛔⭐ **예시 낱말을 어느 필드에도 넣지 않는다 — 전 필드가 색인된다.**
   `req`·용어 키·**용어 값**·`tables`·`files`·**`note`** 가 전부 건초더미에 들어간다. 색인 안 되는 필드는 **없다.**
   ⇒ 예시가 필요하면 **낱말이 아니라 성격**을 쓴다(원문 인용 금지).
   자기점검: 기록을 넣은 뒤 그 낱말로 조회해 엉뚱한 게 1위면 오염된 것이다.
2. **행동은 지침, 사실은 그래프** — 「다음 세션이 이걸 안 읽으면 같은 실수를 하나」 → 그러면 지침(`.claude/rules/`)이다. 그래프는 그 주제를 물을 때만 걸리고 지침은 매 세션 로드된다
3. **원천 3분류** — 사람이 쓴 것(티켓 원문 · 인수인계 문서 · 담당자 답변)은 ⭕ 옮긴다 · 코드 구조(경로 · 건수 · 컬럼)는 ⛔ 넣지 않고 도구로 조회한다(**명령**을 적는다) · 해석 · 인과 · 「실제로 쓰나」는 ⛔ 자동 추출하지 않는다 — 실패 모드가 빈 칸이 아니라 그럴듯한 오답이다
4. **근거 등급** — 단일 증거로 단정하지 않는다. 「버그다」 전에 호출 사슬을 끝까지 읽고, 다 못 읽었으면 「A 만 보면 …인데 B 는 확인 못 했다」로 `note` 에 `⚠️ 미확정` 을 붙여 넣는다. 짜기만 하고 안 돌린 것은 `req` 에 `(조사만, 미실행)`. ⛔ 새 원천(문서 · DB 코멘트 · 담당자 답변 · 지난 세션 기록)도 단일 증거다 — 기존 기록과 어긋나면 어느 쪽도 먼저 믿지 않고 데이터로 재판정한다
5. **같은 주제의 살아있는 기록이 2건 이상이면 정본 1건으로 통합한다** — `"supersedes":["<req1>","<req2>"]` 로 전부 무효화하고 정본 `req` 는 `정본: ` 으로 시작한다. 안 하면 같은 주제가 불어나 각자 같은 정정을 반복한다

## 5. 하다 만 것 — `note` 를 `⏸` 로 시작한다

```json
{"req":"…", "note":"⏸ 어디까지 했고 왜 멈췄나 · 재개하려면 무엇만 받으면 되나"}
```

랭킹으로는 못 닿는다 — 광역 기록이 도메인 낱말을 독점한다. `⏸` 가 유일한 노출 경로다: 훅이 순위 밖이어도 붙여 주고 `--open` 이 전부 보여준다.
표식은 `note` **맨 앞**에서만 인정한다. 재개해서 끝냈으면 `supersedes` 로 무효화한다 — `⏸` 를 지우는 것으로 갈음하지 않는다.

## 6. 낡으면 그 자리에서 무효화한다 — 새 기록 추가로 갈음하지 않는다

판단 기준: **「이 기록을 그대로 믿고 작업하면 틀리나」** — 틀리면 낡은 것이다. ⛔ 미루면 그 정정이 뒤따르는 기록마다 복제된다.

| 낡은 것 | 할 일 |
|---|---|
| 이전 기록 전체 | 새 기록에 `"supersedes":"<이전 req>"` |
| 같은 주제 2건 이상 | `정본: <주제>` 1건으로 통합 (4-5) |
| 한 대목만 (미확정이 풀렸다 · 값이 틀렸다) | 원래 기록의 그 문장을 직접 고친다 |

`supersedes` 는 `req` 문자열로 잇는다 — 한 글자만 달라도 끊긴다. 별개 작업이면 비운다. 설계 때 용어(`설계 용어 — 구현 후 재확인`)가 구현에서 바뀌었으면 구현 이름으로 맞춘다.

## 7. 끝내기 전에

```bash
node .harness/tools/graph-find.mjs --check     # 사슬 · 경로 · 용어 선점 · ⏸ 표식 — ⛔ exit 0 이어야 한다
node .harness/tools/graph-find.mjs <방금 넣은 용어>   # 걸리는가 · 엉뚱한 게 1위가 아닌가 (4-1 자기점검)
```

## 8. 훅 — 질문마다 조회를 대신 돌린다

**살아있는 기록 20건 이상 + `--check` exit 0 + 상위3 점유 < 50%** 가 되면 켠다. 점유는 확신 질의 중 가장 자주 1위를 한 기록 3개가 1위인 비율이다 — 질의 집합(이슈 제목 export)이 없으면 앞의 둘만 보고, 보고에 「독점 미측정」을 쓴다. 소급 측정: 20건 42% · 50건에서 재상승 — 켠 뒤에도 잰다.

```bash
node .harness/tools/graph-measure.mjs . --tickets <이슈 제목 json>   # 「상위3 점유 n%」
node .harness/tools/policy-apply.mjs --local --with graph-hook    # 로컬 전용 모드 (공유 모드는 --local 없이)
```

훅은 상위 2건(정본이 1위면 1건)만 넣고, 신호가 약하면(최고점수 ≤ 2) 침묵한다. 대체된 기록과 `TODO 갱신` 사무 기록은 넣지 않는다.
