# 그래프 — 요구 → 용어 · 파일 · 함정

> 상태: **설계안** · 기록은 자동 로드되지 않는다. 조회로만 읽어서 무한히 쌓여도 세션 비용이 0이다

같은 것을 두 번 조사하지 않고, 사용자의 말과 코드의 이름 사이에 다리를 놓는다. 값은 `terms`(현업 용어 → 실체)와 `note`(함정)에 있다 — 파일 목록만 쌓으면 git 의 열등한 사본이다.

## 3. 작업이 끝나면 — 파일 목록 보고와 한 세트로 (`final-gate` 의 기록 단계)

**첫째 문 — 이 저장소의 지식인가.** 도메인 · 코드 · 데이터 · 운영 절차가 아니면 기록하지 않는다 — 답하고 끝낸다(아래 「남길 게 없으면」 한 줄에 `도구 지식`). Claude Code · 플러그인 · 훅 · IDE · 터미널 · 이 하네스의 사용법은 어느 저장소에서나 같고, 그래프는 이 저장소를 이어받을 사람을 위한 것이다. 예외: 이 저장소의 파일(하네스 설정 · 도구 포함)을 실제로 고쳤을 때(그 파일을 `files` 에) · 이 저장소가 무엇을 들이고 뺐나의 결정(가리킬 파일이 없으면 `"scope":"meta"`). `graph-append` 가 파일 · 테이블을 하나도 안 가리키는 기록을 이 순서의 안내로 거부한다(참조 머리말 · `scope:meta` 는 통과) — 통과하려고 상관없는 파일을 넣지 않는다. 「파일 목록 보고와 한 세트」가 이 문을 건너뛰게 하지 않는다 — 걸렀으면 그 한 줄이 그 세트다.

```bash
node .harness/tools/graph-append.mjs <<'EOF'
{"req":"<사용자 요구 한 줄>",
 "terms":{"<현업 용어>":"<시스템에서 무엇인가 — 테이블·URL·컬럼·서비스>"},
 "files":["<실제로 만진 파일>"],
 "note":"<다음 사람이 알아야 할 함정 한 줄 · 기각한 대안 한 줄>"}
EOF
```

- `terms` 는 객체로 — 배열이면 해석이 사라진다. `files` 에 줄번호를 붙이지 않는다. `note` 는 한 줄 · 800자까지 — 넘으면 도구가 거부한다(긴 note 는 다른 질문의 1위를 가로챈다 — 주제별 기록으로 나눈다). 남길 게 없으면 보고에 `그래프: 기록 안 함 — <이유>` 한 줄 — 줄 맨 앞에 이 머리말 그대로
- **기록 단위는 「이 용어들이 같은 질문에서 함께 필요한가」** — 함께면 주제 기록 1건, 갈리면 2~3건. 광역 사전 1건에 몰아넣으면 그 기록이 적중을 독점하고, 용어 1개짜리로 쪼개면 `req` 가 빈약해 정확일치를 못 받는다
- 커밋에서 만든 기록은 `terms` 를 채워야 값이 있다 — 커밋 제목만 넣으면 0 이다
- ⛔ **개인 식별자(사번·이름·연락처·계정)와 비밀값을 적지 않는다** — 공유 모드에서는 그대로 커밋된다. 사람은 역할로, 이슈는 번호 없이 요지로

## 7. 끝내기 전에

기록을 고친 뒤에 `node .harness/tools/graph-find.mjs --check` — exit 0(사슬 · 경로 · 용어 선점 · ⏸ 표식)

## 8. 훅 — 질문마다 조회를 대신 돌린다

훅은 대체된 기록과 `TODO 갱신` 사무 기록을 넣지 않는다.
