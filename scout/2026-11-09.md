## 이번 주 추천 (2건)

### 1. ⭐ Claude Code 2.1.319 로 CLI 올림 — 권한 우회 수정 3건이 키트 deny 정책에 닿는다
- 종류: 구조(설정 아님, CLI 버전)
- 무엇: 2.1.319 의 수정 — ① 「Bash deny · ask 규칙이 따옴표 낱말로 쓴 명령을 놓치던 것」 ② 「조작한 환경변수 접두어가 명령 일부를 권한 검사에서 숨기던 Bash 우회」 ③ 「`sed` 가 accept-edits · auto 모드에서 권한 검사를 건너뛸 수 있던 것」. 또 `timeout 30 rg foo` 같은 읽기 전용 명령의 불필요한 승인 요청 제거. (출처: [CHANGELOG 2.1.319](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md))
- 왜 우리에게: 키트의 안전은 `policy/settings.json` 의 deny(`git push` · `reset --hard` · `git clean` · `rebase` · `curl|bash` …)에 기댄다. ①②는 그 deny 가 뚫리던 경로라, 낮은 버전 PC 는 정책이 약속한 만큼 막지 못한다. 다른 PC(macOS) 도 같은 버전인지 확인할 가치가 있다.
- 가장 작은 도입: 코드 0줄. 두 PC 에서 `claude --version` 확인 후 2.1.319 미만이면 갱신. (선택) SETUP · structure §3 에 「deny 가 약속대로 돌려면 CLI 2.1.319 이상」 한 줄 — 문서 1줄, 사용자 결정.
- 위험: 없음(CLI 갱신만). 같은 버전의 auto 모드 변경(텔레메트리 · 기능 플래그가 꺼져 있으면 서버 확인이 안 되는 호출은 묻거나 거부, 폴백 없음)이 있어 사내 게이트웨이를 쓰는 PC 는 동작이 달라질 수 있다 — 해당 시 `CLAUDE_CODE_AUTO_MODE_SERVER=0`.
- 사전 시험: `CLAUDE_CONFIG_DIR=<임시 폴더>` 에서 새 버전으로 샘플 프로젝트에 deny 규칙 하나(예: `git clean`)를 따옴표 낱말로 써서 막히는지 확인.

### 2. `permissions.denyInsteadOfPrompting` — 무인 실행에서 승인 대기로 멈추지 않기 (조건부)
- 종류: 구조(설정 키 1개)
- 무엇: 2.1.319 신설. 승인 프롬프트에서 대기하게 될 도구 호출을 거부하고 턴을 이어간다(터미널 세션 · 서브에이전트 · 팀원 모두). (출처: [CHANGELOG 2.1.319](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md))
- 왜 우리에게: `docs/plan.md` 의 ⏸ 항목들(다른 세션이 승인 대기)과 직접 이어지는 근거는 이번에 못 찾았다. **우리가 실제로 겪은 문제와 연결되지 않아 추천 강도는 낮다** — 서브에이전트 주도 개발에서 승인 대기로 멈추는 사례가 생기면 그때 쓴다. 새 설정 키이므로 키트에 넣으면 감점.
- 가장 작은 도입: 키트에는 넣지 않는다. 필요한 프로젝트가 자기 `settings.local.json` 에 한 줄.
- 위험: 거부된 호출이 조용히 작업을 비틀 수 있다(final-gate · verify 가 막히면 증거 없이 끝났다고 말할 위험) — 켜면 verify 호출이 allow 에 있는지 먼저 확인.
- 사전 시험: 임시 `CLAUDE_CONFIG_DIR` + 샘플 프로젝트에서 ask 규칙 명령을 시켜 거부 후 턴이 계속되는지 확인.
