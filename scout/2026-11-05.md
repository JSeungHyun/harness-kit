### 2. ⭐ Claude Code 내장 `/verify` 와의 관계 확인 (지울 수 있나)
- 종류: 구조
- 무엇: 번들 스킬 `/verify` — 앱을 직접 빌드 · 실행해 변경이 동작하는지 확인(테스트 · 타입검사에 기대지 않음). 사용자가 직접 입력해야 돌고, v2.1.215 부터 Claude 가 자동 호출하지 않는다. `disableBundledSkills` 로 끌 수 있다. (출처: [공식 skills 문서](https://code.claude.com/docs/en/skills) — 검색 요약 기준, 직접 읽지 못함 · [CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md) 2.1.309/312)
- 왜 우리에게: 이름이 키트의 `verify` 도구 · 「verify exit 0」 증거 · 관문 훅의 신호(verify 를 돌린 턴)와 겹쳐 보인다. 다만 키트 `verify` 는 `checks[]` 를 결정론적으로 돌리는 도구이고 내장은 앱 실행 확인이라 **대체는 아니고 보완**일 가능성이 크다. 지우기 후보는 없다 — 이 추천의 실익은 「혼동 방지」다.
- 가장 작은 도입: 바꿀 코드 0줄. 확인할 것 2가지 — (a) 슬래시 `/verify` 가 모델이 Bash 로 부르는 `verify` 와 이름이 부딪쳐 final-gate · 규칙 문장이 헷갈리지 않는가, (b) final-gate 의 「운영 데이터 · 설정 · 조사」 증거 행에 「앱을 실제로 띄워 본 확인」용으로 한 줄 언급할 가치가 있는가. 둘 다 아니면 기각.
- 위험: 없음(읽기만). 내장 `/verify` 동작 세부는 미확인.
- 사전 시험: `CLAUDE_CONFIG_DIR=<임시 폴더>` 로 샘플 프로젝트에서 `/verify` 한 번 돌려 출력 확인.
