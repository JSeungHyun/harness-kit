# graph 이식 명세 — 깨지면 안 되는 것

> 상태: **설계안** · 출처: context-graph 를 실제로 운영한 세션의 답변(2026-10-02). 예시는 전부 일반화했다.
> ⭐ **키트가 정본이다**(2026-11-10 사용자 결정 · 13차). 그래프 도구는 키트 `tools/graph-*.mjs` 한 벌이고, 모든 설치가 「갱신」으로 같은 판을 받는다 — 설치마다 다른 것은 `harness.json` `graph` 설정뿐(§4). context-graph 저장소는 보관했다 — 따라가지 않는다. 바꿀 것은 그래프가 가장 깊은 설치(원천)의 세션과 「실제로 더 낫다 / 바꿔 보니 별로였다」를 주고받아 정하고, 키트에서 §6 시험 틀을 거쳐 개발한다. 13차 화해로 원천 판에만 있던 동작(이름 필터 · 저장소 밖 주제)을 넣었고, 같은 기록 재생 883건에서 원천 판과 훅 출력이 모두 같다(`docs/proof.md`).
> ⛔ 아래 8개는 **실측 사고로 만들어진 동작**이다. 특성 테스트 없이 옮기면 그 사고가 되돌아온다.

## 1. 특성 테스트로 잡을 동작 8개

| # | 동작 | 예시 | 없을 때 일어난 일 |
|---|---|---|---|
| ① | **대체된 기록은 기본 검색에서 빠진다** (`--all` 로만) | A `req="로그인 실패 처리"` `terms={"재시도":"3회 후 잠금"}` · B `req="정본: 로그인 실패 처리"` `supersedes="로그인 실패 처리"` → 「재시도」는 B 만. `--all` 이면 둘 다, B 에 `↑ 이전을 대체`, A 에 `↓ 대체됨` | 감점(동점 뒤로)으로만 했더니 본문이 긴 대체 기록이 10점으로 정본 6점을 눌렀다. ⛔ **제외**로 구현한다 |
| ② | **정확일치가 점수 합을 이긴다** — 정렬 첫 키가 정확일치 유무, 점수는 둘째 키 | A `terms={"캐시무효화": …}` (정확일치 1 = 3점) · B 흔한 낱말이 5군데 스침(합 5점) → 「캐시무효화」 1위는 A | 합만으로 세우면 1위가 정확일치 0 인 비율 39% → 고친 뒤 11% |
| ③ | **용어 「값」은 한글 낱말 조회에서 빠지고 식별자 조회에만 들어간다** — 판별은 「토큰에 한글이 있나」 | A `terms={"배치": "매일 02시에 도는 스케줄러 …(장문)"}` → 「스케줄러」(한글) 안 걸림 · 「CronTrigger」(값에만 있는 식별자) 걸림 | 값까지 넣으면 긴 기록이 아무 질의나 이긴다 — 1위가 정확일치 0 인 비율 56% |
| ④ | **침묵 문턱 — 최고점수 ≤ 2 면 출력 0 바이트** | 「응 그렇게 해줘」 · 「계속 진행」 → 아무것도 안 낸다 | 3 으로 올리면 그래프에 답이 있는 업무 질의가 침묵한다. 실측 192건 중 `s ≤ 2` 로 침묵된 23건은 전부 진행 발화이거나 답이 없는 질의였다 |
| ⑤ | **1단 상한 — 카드 2장, 1위가 `정본: ` 이면 1장** | 기록 10건, 확신 판정 통과 → 2장 이하 · 1위가 정본 → 1장 | 상한이 없으면 비용이 기록 수에 비례한다. 정본 1장 규칙: 7,128자 → 4,924자 |
| ⑥ | **`⏸` 는 랭킹과 무관하게 붙는다** | A `note="⏸ 설계까지 했고 승인 대기"` (점수가 낮아 순위 밖) · 그 주제의 질의가 최고점수 ≥ 5 → `⏸ 열린 작업 N건` 줄로 따로 · 4건 이상이면 질의와 가장 겹치는(정확일치 → 점수 → 최신) 3건만 펴고 `  … 나머지 N건: node .harness/tools/graph-find.mjs --open` 한 줄 — 머리줄 N 은 전체 건수 | 보류 기록이 그 작업을 재개하는 요청에서 10위라 표시 한도 밖이었다. ⛔ 랭킹에 섞지 않는다 — 상태 축이다. (상한 전) 열린 작업 16건인 원천에서 실입력 300 중 122회에 붙어 그 부분만 p90 5,902자 |
| ⑦ | **문장을 통째로 주면 토큰으로 쪼개 다시 찾는다** | 「로그인할 때 재시도가 몇 번인지 알고 싶어」 → 1차 부분일치 0건 → 토큰 분해 재검색 → `(문장을 토큰 N개로 나눠 다시 찾았다)` | 없으면 0건이 나와 「새 영역이다」로 오도한다 — 기록이 있는데 없다고 답하는 가장 비싼 실패 |
| ⑧ | **`--check` 가 대체 사슬 4종을 잡는다** — 하나라도 있으면 exit 1 | 고아 대체(가리키는 req 없음) · 기록순 역행(앞 줄이 뒷 줄을 대체) · 자기 대체 · 중복 대체(한 req 를 2건 이상이 대체) | ⛔ **경로 무결성 검사는 대체된 기록을 뺀다** — 경로가 사라진 것이 대체된 이유인 경우가 많아, 안 빼면 영구 오탐으로 `--check` 가 늘 exit 1 이 되고 사람이 무시한다 |

보너스: `files` 에 줄번호(`a/b.js:120`)를 붙이면 존재 검사와 역방향 조회가 빗나간다 — 도구가 걸러내는지도 본다.

## 2. 훅 — 실제로 돈 설정과 바꾸면 안 되는 출력

```json
{
  "hooks": {
    "UserPromptSubmit": [{
      "hooks": [{
        "type": "command",
        "command": "node",
        "args": ["${CLAUDE_PROJECT_DIR}/.harness/tools/graph-hook.mjs"],
        "timeout": 30,
        "statusMessage": "그래프 조회 중..."
      }]
    }]
  }
}
```

- `matcher` 없음(전체 프롬프트) · `timeout: 30`(실측 평균 1.6초 · 최대 6.7초 · 277회 중 8회 초과)
- exec 형식(`command` + `args`) — 셸을 띄우지 않고 node 를 바로 띄운다. 경로에 공백이 있어도 따옴표가 필요 없다. 원천의 셸 형식(`node "$CLAUDE_PROJECT_DIR/..."`)은 Windows 에서 Git Bash 를 한 번 더 띄운다(2026-11-05 이 PC 실측 중앙값 1.61 → 1.13초, Claude Code 2.1.318). 옛 등록은 `policy-apply` 가 새 형식으로 바꿔 끼운다
- 스크립트 몫은 36ms 이고 나머지는 Node 기동이다 — 느리면 환경을 의심한다

⛔ **출력 문장 — 전부 실패로 만들어진 것이라 바꾸지 않는다** (특성 테스트가 문자열로 지킨다):

1. 1단 머리글의 탈출구 — 「위 기록이 이 질문에 답하지 않으면 그렇다고 말하고 평소대로 코드를 탐색한다 — 걸린 것이 답이라는 뜻은 아니다」 (광역 기록 12개가 적중의 71% 를 독점 — 없으면 관련만 있는 카드로 답을 지어낸다)
2. 「⛔ 값이 「제거됨」·「바뀜」으로 시작하면 그게 답이다. 코드에 안 보인다고 「모름」이라 하지 않는다」
3. 「… 이 질의와 안 걸린 항목 N개(키만): 키A · 키B」 — 잘라낸 게 아니라 접었다는 신호(주입 −21.6%, 정답 손실 0)
4. 「⏸ 열린 작업 N건 — 이 주제에 하다 만 기록이 있다. 다시 조사하기 전에 이것부터 편다」
5. 2단 머리글 「⛔ 억지로 고르지 않는다 — 관련 없으면 색인을 무시하고 평소대로 코드를 탐색한다」
6. 마지막 줄 「더 볼 것: node … graph-find.mjs <어근> (어근은 짧게, 여러 개)」 — 경로만 `.harness/tools/` 로
7. ⏸ 접힘 줄 「  … 나머지 N건: node … graph-find.mjs --open」 — 접었다는 신호와 전부 보는 길. 머리줄(4번)의 N 은 접기 전 전체 건수다(14차)

정확한 원문은 키트 `tools/graph-hook.mjs` 다 — `test/graph.test.mjs` 가 문자열로 지킨다(7번은 `test/graph-hook-cap.test.mjs`).

**파일 기록 훅(선택 · 14차).** `policy/graph-read-hook.json` — PostToolUse(Read) → `.harness/tools/graph-read-hook.mjs`. 모델이 연 파일을 `files` 로 통째로 가리키는 살아있는 기록을 붙인다: 최신 정본 1건 + 함정 1줄(200자) + ⏸ 최대 3건 + 「그 밖 N건 → graph-find --files」, 10건 넘게 걸린 파일은 건수만. 세션 · 에이전트마다 파일 · 기록 한 번, 같은 턴에 프롬프트 훅이 붙인 기록은 세션 기록 끝을 거슬러 읽어 뺀다(서브에이전트는 빼지 않는다). PreToolUse · PostToolUse 모두 `hookSpecificOutput.additionalContext` 가 도구 결과 옆에 닿고 일반 stdout 은 안 닿는다(2.1.322 실측) — Post 를 쓴 이유는 성공한 읽기에만 돌고 권한 결정 통로가 아니어서다. 원천 30일 재생: 비용은 프롬프트 훅의 2.2%(세션 p90 2.9%), 빈틈 96건 중 66건이 프롬프트 훅을 못 받는 서브에이전트, 표본 관계있음 13/20. Read 만 보므로 Bash(`cat` · `sed -n`)로 본 파일(기록 파일 보기의 약 2/3)은 덮지 않는다.

## 3. `templates/rules/graph.md` — 넣을 절 (우선순위순, ~95줄)

| | 절 | 왜 |
|---|---|---|
| 1 | 탐색은 그래프부터 (`graph-find` 1번) | 이 구조의 전부 |
| 2 | 종료 시 기록 — 파일 목록 보고와 한 세트 · 첫째 문 「이 저장소의 지식인가」 · 남길 게 없으면 `그래프: 기록 안 함 — <이유>`(관문 훅이 본다 · 14차) | final-gate 로 이어진다. 형식 판정(변하나 · 재조회로 되나)만으로는 도구 사용법 조사가 통과하고, 「한 세트」가 「답했다 → 기록한다」로 직행시킨다 — 운영 그래프에서 실제로 났다. 설치 직후가 하네스 이야기를 가장 많이 하는 시점이라 이식하면 더 커진다 |
| 3 | `supersedes` + 무효화 대상 표 | 미루면 정정이 기록마다 복제된다(같은 주제 6건) |
| 4 | `⏸` 는 `note` 를 그것으로 시작 | 유일한 노출 경로 |
| 5 | ⭐ **예시 낱말을 어느 필드에도 넣지 않는다** + 자기점검 | 아래 |
| 6 | 용어 키는 사용자의 말, 값은 시스템의 실체 | 공식 용어를 키로 적으면 다음에도 못 찾는다 |
| 7 | 끝내기 전 `--check` exit 0 | 실제 호출의 36% |
| 8 | 코드 탐색은 세 경우만 | 기록을 안 믿으면 기록 비용만 남는다 |
| 9 | 단일 증거로 단정하지 않는다 — 「버그다」 전에 호출 사슬 끝까지 | 범용 |
| + | 훅을 켜는 조건 · ⛔ 개인 식별자 금지 | 설계서 §5 |

⛔ 는 되돌리기 어렵거나 파괴적인 금지(개인 식별자 · 비밀값 등)에만 쓴다 — 규칙 파일마다 상한을 `test/rule-emphasis.test.mjs` 가 지킨다(14차, design §8).

⭐ 5번 원문 그대로:

> **예시 낱말을 어느 필드에도 넣지 않는다 — 전 필드가 색인된다.**
> `req`·용어 키·**용어 값**·`tables`·`files`·**`note`** 가 전부 건초더미에 들어간다. 색인 안 되는 필드는 **없다.**
> ⇒ 예시가 필요하면 **낱말이 아니라 성격**을 쓴다(원문 인용 금지).
> 자기점검: 기록을 넣은 뒤 그 낱말로 조회해 엉뚱한 게 1위면 오염된 것이다.

왜: 원래 이 자리에 「예시는 `note` 에 쓴다, 가중치가 낮아 정본을 밀지 않는다」는 **틀린 규칙**이 있었다. 문제는 순위가 아니라 **도달**이라, 그 규칙을 따라 하루에 세 번 오염시켰고 세 번 다 손으로 고쳤다.

**판단 규칙 상위 5 — 「어겼을 때 실제로 사고가 났나」 순** (위 표의 5·2·9 와 겹치는 것은 이 문장으로 쓴다):

1. 예시 낱말을 어느 필드에도 넣지 않는다 + 자기점검 (위 원문)
2. **행동은 지침, 사실은 그래프** — 「다음 세션이 이걸 안 읽으면 같은 실수를 하나」 → 그러면 지침. 그래프 용어는 그 주제를 물을 때만 걸리고 지침은 매 세션 로드된다 (graph.md 가 왜 따로 있는지의 설명이다)
3. **원천 3분류** — 사람이 쓴 것(티켓 원문·인수인계 문서·담당자 답변)은 ⭕ 옮긴다 · 코드 구조(경로·건수·컬럼)는 넣지 않고 도구로 조회한다 · 해석·인과·「실제로 쓰나」는 자동 추출하지 않는다 — 실패 모드가 빈 칸이 아니라 그럴듯한 오답이다
4. **근거 등급** — 사슬을 다 못 읽었으면 「버그다」가 아니라 「A 만 보면 …인데 B 는 확인 못 했다」로, `⚠️ 미확정` 을 붙여 넣는다 (살아있는 기록의 24% 가 미확정 표기 — 정상 비율)
5. **같은 주제의 살아있는 기록이 2건 이상이면 정본 1건으로 통합** — `"supersedes": [...]` 로 전부 무효화하고 정본 `req` 는 `정본: ` 으로 시작 (안 지키면 같은 주제가 6건으로 불어나 각자 같은 정정을 반복한다)

⛔ 규칙으로 쓰지 않는 것 — 기계가 잡는다: 「소급 기록에 supersedes 금지·date 필수」(`--check` 의 시간 역행이 잡는다) · 「미확정 해소 시 원래 표기도 고친다」(「낡은 기록은 그 자리에서 고친다」에 포섭된다).

**뺄 것:** `writing-plans` 를 쓰지 않는다는 흐름 절(harness.md 가 정한다) · PostgreSQL DB 코멘트 절(프로젝트 몫) · 어휘 다리 문서·관통 추적기 안내(프로젝트 고유) · `--promote`·`graph-view` 안내(SETUP 에만) · 운영 요건 우선 절은 **선택 절**로(운영 업무가 있는 프로젝트만 — SETUP 이 묻는다).

## 4. 원천과 달라진 출력 · 설치마다 다른 것

| | 출력(키트 판) | 주의 |
|---|---|---|

## 6. 그래프를 바꿀 때의 시험 틀 (2026-11-10 · 13차)

그래프 도구 · 기록 규칙 · 훅을 바꾸는 변경은 아래 네 층을 모두 거친다. 앞의 둘은 `npm test` 에 들고(실패 = exit 1), 셋째는 실제 설치 사본에서 돈다. ⛔ 회사 · 프로젝트 데이터는 이 레포에 넣지 않는다 — 합성 픽스처만 레포에, 실데이터 재생은 설치 쪽에서 돌리고 **숫자만** `docs/proof.md` 에 적는다.

**L1 합성 특성 시험 — 기록 상태 × 질의 종류** (`test/graph-frame.test.mjs`). 픽스처 그래프 하나에 아래 상태를 모두 두고, 질의마다 기대(1위 · 침묵 · `--check` 결과)를 표로 단언한다.

쓰기 쪽도 같은 틀로 본다: 정상 · 여러 줄 note · 상한 초과 · 저장소 밖(파일 · 테이블 없음) · `scope:meta` · 별칭 · 깨진 입력 · 줄번호 경로(떼고 씀) — 각각 exit 0/1 을 단언한다. 채택 안 한 것: 없는 파일 · 이번 변경 목록 밖 파일 · 높은 겹침인데 supersedes 선언 없음.

**L2 변형 시험 — 같은 픽스처를 자동으로 비튼다(시드 고정 · `test/graph-frame.test.mjs`).** 칸 삭제 · req 삭제 · 경로 이름 바꾸기 · supersedes 순서 뒤집기 · 기록 복제 · note 부풀리기 · 지시문 끼우기 · 줄 순서 섞기 · CRLF · BOM · **한글 NFC/NFD**(macOS 에서 온 파일) · 공백 변형. 불변식: 죽지 않는다 · 같은 입력이면 같은 출력 · `--check` 종료 코드가 변형 종류와 맞는다 · **변형과 무관한 질의의 1위는 그대로**. 처음 돌렸을 때 BOM(첫 줄이 깨진 줄로 사라짐)과 NFD(한글 질의가 하나도 안 걸림)가 실제로 깨졌다 — 이제 읽을 때 BOM 을 떼고 NFC 로 맞춘다.

**L3 실데이터 재생 — 설치 사본에서, LLM 없이(결정적).** 도구: `node .harness/tools/graph-measure.mjs --baseline <도구 폴더> --store <기록> --tickets <json> [--guard self,share]` — 같은 기록에 기준선 폴더의 `graph-find` · `graph-hook` 과 지금 판을 돌려 자기검색 1위 · 티켓 확신(1단) · 침묵 · 주입 크기 평균 · p90 · 상위3 점유와 「훅 출력 같음 n/N」(티켓 + 기록 req 전부, 경로 표기 차이는 같은 것으로)을 나란히 내고, `--guard` 지표가 기준선보다 나쁘면 exit 1 이다. 아직 도구에 없는 것: 실제 입력 프롬프트 재생 · 업무어 질의 묶음 · (정답 커밋이 이어진 티켓이 있으면) 정답 파일 적중 hit@1 · hit@2 — 이것은 시각으로 자르지 않고 **티켓별 제외**(그 티켓을 인용한 기록 · 정답 파일을 가리키면서 date 가 정답 커밋 이후인 기록을 빼고)로 돌린다. 원천 실측(11-10): date 는 사건 날짜 · recorded 는 쓴 날짜이고 소급 기록 · 제자리 수정(277건 중 70건)이 있어 시각 자르기는 비거나 누수다. 바꾼 판이 의도한 지표 밖에서 기준선보다 나빠지면 그 변경은 넣지 않는다 — 의도한 악화는 원천 세션과 합의하고 이유를 남긴다. 원천은 기록 · 세션 기록 · 티켓 파일 그대로, 결과 숫자만 `docs/proof.md` 로.
- 티켓별 제외는 정답 집합이 그래프보다 먼저면 그래프를 비운다 — 14차 A1: 2022~2026-09 티켓(그래프는 2026-09~)에서 정답 파일을 아는 더 이른 기록이 남은 티켓 4/95 · 훅 hit@2 1/95. 그 숫자는 그래프 성능이 아니다 — 정답 집합은 그래프가 생긴 뒤의 일로 고르고 `recorded` 로 되감는다(plan 14차 후보 11)
- 세션 기록 재생에서 기록을 시점으로 거를 때 날짜(`recorded` · `date`)로 자르면 샌다 — 그날 그 턴이 끝에 쓴 기록 · 나중에 제목을 바꿔 다시 쓴 기록이 들어온다(14차 파일 기록 훅: 카드 96건 중 18건). 같은 날 기록은 그 req 를 쓴 도구 호출 시각이 그 사건보다 앞일 때만 넣는다
- 1위 독점 절 옆에 「정확일치 0 으로 1위」 수는 두지 않았다(14차) — 원천의 알려진 가로채기는 정확일치(구 배열형 terms 의 광역 키)로 이겨 이 축에 0 으로 나왔다
