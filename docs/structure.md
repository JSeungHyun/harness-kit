# 구조 — 큰 그림 · 훅 · 검증 · 구성

> 상태: **설계안** · 대상에 설치된 모습 기준이다. 왜 그렇게 정했나는 [design.md](design.md), 그래프가 깨지면 안 되는 동작은 [graph-port.md](graph-port.md)

## 0. 큰 그림

키트는 **두 모듈**이다. **증거**는 「끝났다」를 모델이 아니라 도구가 판정하게 하고, **그래프**는 사용자의 말 → 코드 위치 · 함정을 기록해 같은 조사를 두 번 하지 않게 한다.
일의 흐름(설계 · TDD · 서브에이전트)은 키트가 아니라 **superpowers** 플러그인이, 과설계 점검은 **ponytail** 플러그인의 `/ponytail-review` 가 맡는다.

| 모듈 | 하는 일 | 구성 |
|---|---|---|
| 증거 | 완료를 도구로 판정 | `verify` · 규칙의 `/code-review` 한 줄 |
| 그래프 | 요구 → 용어 · 파일 · 함정 기록과 조회 | `graph-*` 도구 · 기록 파일 · 그래프 훅(조건부) |

**한 턴의 흐름**

```
사용자 질문
  └ [그래프 훅] 관련 기록을 찾아 붙인다 (기록이 쌓인 뒤에만 켠다)
작업 — 흐름은 superpowers (설계 → TDD · 서브에이전트 → 디버깅)
  └ verify           「끝났다」를 도구가 판정 (검사가 덮지 않은 코드면 /code-review)
```

**키트가 아닌 것** — superpowers · ponytail 의 훅과 스킬, 프로젝트가 더한 훅은 §8 에 따로 둔다. §1~§4 는 키트 것만 다룬다.

## 1. 훅 — 늘 거는 것 하나 · 선택 하나

| 훅 | 언제 | 하는 일 | 켜는 때 |
|---|---|---|---|
| 서브에이전트 상한 훅 `agent-cap.mjs` (10초) | `PreToolUse`(`Agent|Task`) · `SubagentStart` · `SubagentStop` — 서브에이전트를 부르고 시작 · 끝낼 때만 | 동시에 도는 서브에이전트가 2개면 셋째 호출을 거부하고 이유(지금 도는 수 · 끝난 뒤 다시)를 모델에게 준다. `web-fetch` 는 세지 않는다 · 끝 소식이 없는 기록은 3시간 · 시작 안 한 예약은 60초 뒤 잊는다 · 상태는 `os.tmpdir()/harness-agent-cap/<session_id>.json` | 모든 설치 — `policy-apply` 가 `--only` · `--clean` 에도 건다 |
| 그래프 훅 `graph-hook.mjs` (30초) | `UserPromptSubmit` — 질문을 칠 때 | 프롬프트로 그래프를 조회해 카드 1~2장 · 후보 색인 · 침묵 중 하나를 넣는다 (§6.4) | ⛔ 조건부 — 기록이 쌓인 뒤 (§6.4) |

- `Stop` 관문 훅(`gate-hook`)은 22차에 걷었다 — 덜어낸 판(관문 훅 끔 + 규칙 두 파일 덜기)이 코드 비용 0.48 · 시간 0.60 · 나쁜 실행 3/36 대 1/36 · 질문 적중 24 대 24 로 미리 적은 기준을 넘었다(`docs/proof.md` 「23차」). 갱신이 설치본의 도구 · 정책 파일을, `policy-apply` 가 훅 등록을 걷는다
- 이 밖에 git `pre-commit` 훅이 하나 있다 — `scan-shared.mjs`, **공유 모드만**. 커밋되는 기록 · 규칙에 민감 정보 패턴이 있으면 막는다
- 나머지는 훅이 아니라 규칙이 「언제 무엇을 부르라」고 시킨다(`harness.md` — 완료는 증거로)
- 설정은 `policy-apply` 가 `.claude/settings.json`(공유) 또는 `settings.local.json`(로컬)에 병합한다 — ⛔ 덮어쓰지 않는다. 권한은 합집합이고 프로젝트가 더한 훅은 그대로 둔다(예: §8.2)
- 훅은 셸 없이 node 를 바로 띄운다(exec 형식 `"command": "node", "args": ["${CLAUDE_PROJECT_DIR}/.harness/tools/…"]`) — Windows 에서 Git Bash 를 거치지 않아 한 번에 약 0.5초 덜 든다. 옛 셸 형식 등록은 `policy-apply` 가 바꿔 끼우고, 갱신(`upgrade`)이 그 명령을 낸다
- 훅이 실패하면 조용히 통과한다 — 프롬프트와 종료를 막지 않는다
- Claude Code 의 훅 이벤트 33개 중 키트가 쓰는 것은 위 하나(`UserPromptSubmit`)다 — `Stop` 은 22차에 걷었다 — 나머지 30개는 19차에 검토해 후보 0 · 보류 2(압축 자리 — `SessionStart` compact · `PreCompact`) · 기각 28 이다(plan 19차)

## 2. 검증 — 「끝났다」를 무엇으로 판정하나

### 2.1 `verify` — 완료 증거

`.harness/harness.json` 의 `checks[]` 를 전부 돌린다. 하나라도 실패하거나 검사가 0개면 exit 1. 검사마다 선택 필드 `covers`(그 검사가 실제로 돌리는 코드의 glob 배열)를 둔다 — 하나도 없으면 출력 첫 줄이 「코드 검사 없음 — 코드 변경의 증거는 /code-review」다(exit 은 그대로). 형식이 틀리면 로더가 거부한다.

| `kind` | 통과 |
|---|---|
| `junit-xml` | 이번 실행이 쓴 XML 에 testcase 1개 이상 · 기준선 밖 실패 0 |
| `exit-code` | 명령 exit 0 — `--check` 같은 도구 자체 검사 |
| `file-unchanged` | 생성 명령 뒤 `git status --porcelain -- <evidence>` 가 비었다 |
| `output-match` | 명령 exit 0 · stdout 이 `expect` 정규식에 맞는다 |

원래 있던 테스트 실패는 기준선(`verify --baseline`, ⛔ 사용자가 확인한 뒤에만)으로 적어 두고, 그 밖의 실패만 실패로 친다.

### 2.2 (걷음) `final-gate` · 장부 도구

25차에 걷었다 — 호출 0/36 · 위임 0/24(`docs/devices.md`). 완료 증거는 규칙 `harness.md` 의 verify · `/code-review` 한 줄이, 기록 끝 확인은 `graph.md` 3 · 7절이 맡는다. 옛 설치에서는 갱신이 지운다(`policy/removed.json`).

### 2.3 `graph-find --check` — 기록의 무결성

대체 사슬 4종 · 없는 경로 · 같은 용어에서 낡은 기록이 1위 · `⏸` 표식 누락 후보 · 1위 독점(경고만). 앞의 셋이 있으면 exit 1 (§6.3).

## 3. 구성 — 프로젝트에 남는 것

| 층 | 무엇 | 언제 |
|---|---|---|
| 매 세션 로드 | 지시 파일(로컬 `CLAUDE.local.md` · 공유 `AGENTS.md` + `CLAUDE.md`) · `.claude/rules/harness.md` · `.claude/rules/graph.md` | 세션을 열 때 Claude Code 가 읽는다 |
| 도구 | `.harness/tools/*.mjs` | 모델이 Bash 로 부른다 |
| 데이터 | 그래프 `.harness/graph/requests.jsonl` · 기준선 | 도구로만 읽고 쓴다 (§6 · §7) |
| 권한 정책 | `permissions` 의 allow · deny · ask | 도구를 부를 때마다 (아래) |
| 플러그인 | superpowers 를 키트 마켓의 커밋으로 고정 · ponytail 은 그 커밋의 리뷰 스킬 `ponytail-review` 만 — 둘 다 PC(사용자 범위)에서 한 번, 로컬 설치는 프로젝트에 선언하지 않는다 | PC 맞추기 · 설치 · 갱신 때 (`plugin-plan` · SETUP) |

**권한 정책** (`policy/settings.json` — 훅이 아니다)

| | 무엇 |
|---|---|
| allow | 읽기 · 키트 점검 도구(`verify` · `graph-find`) · 읽기 전용 셸 — 키트에서 지운 도구의 allow 는 `policy-apply` 가 걷는다(`policy/removed.json`) |
| deny | `git push` · `reset --hard` · `git clean` · `checkout --` · `rebase` · `curl\|bash` · `npm publish` · `find -delete` — `rm` · `rmdir` 은 두지 않는다: PC(전역)가 정한다. 프로젝트 deny 는 전역 allow 를 이긴다 |
| ask | `--force` · `git restore` · `stash drop·clear` |

⛔ 그래프 쓰기(`graph-append` · `graph-alias`)는 allow 에 없다 — 기본 모드에서는 사람이 승인한다. auto 모드에서는 사람이 아니라 분류기가 판정한다.

## 4. 설치 · 갱신 — 대상에 맞춰 얹는다

| 언제 | 무엇이 |
|---|---|
| 설치 전 판별 | `detect` — 신규 구축인지 기존 이식인지 · 멈출 것(⛔) · 확인할 것(⚠️) · git 을 띄우지 못하면(종료 코드 없는 실패) 판별하지 않고 ⛔ exit 1 — 다시 돌린다 · 스택 단서에 맞는 처방 후보(`policy/recipes.json` — 「검증됨」은 실제 설치에서 쓰는 것, 「후보」는 자동 적용 안 함) |
| 공유 / 로컬 | `install-mode` — 공유는 팀이 같이 커밋하고, 로컬은 설치 경로를 git 에서 숨긴다 · 공유는 기록 파일을 `.gitattributes` 에 `merge=union` 으로 둔다(따로 이어 쓴 기록이 충돌 없이 합쳐진다 — 이식 검사 ⑤ 가 본다) |
| 옛 context-graph 기록이 있는 프로젝트 | 키트 그래프 모듈을 얹고 `harness.json` `graph.store` 가 기존 기록을 제자리에서 잇는다 — 그래프 도구는 모든 설치가 키트 판 하나(13차). 옛 도구(`graph.tools`)로 설치된 곳은 `upgrade` 가 ⛔ 이관 안내 → `upgrade --migrate-graph`(기록 files 의 옛 도구 경로를 한 번 바꿈) · 참조 · 훅은 그 프로젝트가 고친다 |
| 키트가 새 버전이 되면 | `upgrade` — ⛔ 키트에 커밋 안 된 변경이 있으면 아무것도 얹지 않고 exit 1(설치본에 미커밋 판이 커밋 이름으로 적히지 않게) · 도구 · 정책 · 손대지 않은 규칙을 올리고 키트 커밋을 `.harness/kit-commit` 에 적는다 · 프로젝트가 고친 키트 규칙 · 스킬은 ⛔ exit 1 + 다른 줄 요약 — `--own-rules` 가 고친 줄을 `.claude/rules/project-<이름>.md` 로 옮기고 키트 판을 다시 깐다 · 키트에서 지운 것(`policy/removed.json`)을 걷는다(쓴 대장은 남긴다) · 지운 경로를 가리키는 그래프 기록을 알린다 · 빌드 · 테스트 단서가 있는데 `covers` 검사도 「테스트 없음」 선언(`"tests": "none"` + why)도 없으면 ⛔ exit 1(선언 뒤 테스트 소스가 생기면 ⚠️) · 검사마다 처방 id(`recipe`) 또는 `why` 가 없거나 목록에 없는 처방이면 도구 · 규칙은 얹고 ⛔ exit 1 — `harness.json` 은 프로젝트 설정이라 쓰지 않고 적을 줄과 처방 후보만 낸다 · `plugin-plan` — PC 마다 한 번 플러그인을 키트 마켓으로 옮기는 명령(리뷰 스킬은 받은 커밋 · 해시를 옆에 적어 고정 커밋 그대로인지 본다) · 살아있는 그래프 기록이 옛 키트 판을 「지금」으로 적었으면 파일:행 목록(알림만 — 20차) |
| 설치 · 갱신의 끝 | `install-check` — 키트와 같은가 ①~⑨(도구 · 규칙 · 지운 문서 · 정책 · `harness.json` · PC · 지시 파일 import · 동작 · 판). 자리는 `lib/parts.mjs` 의 세 갈래 하나로 정한다 — 키트 소유(같아야 한다 ① ② ⑨) · 프로젝트 설정(모양과 출처만 ⑤ — 검사마다 처방 id 또는 why) · 프로젝트 데이터(무결성만 ⑧). 설정 · 데이터는 판정 줄 아래 「프로젝트 맞춤」 절에 보인다(판정 아님 · 숨기지 않음 — 「테스트 없음」 선언도 여기). ⛔ 하나라도 있으면 exit 1 — 「이식 성공」은 이 판정 줄로만. 키트가 더러우면 판정하지 않는다. ⑨ 는 설치본 커밋 뒤 키트가 문서만 바꿨으면(`lib` · `tools` · `policy` · `templates` 그대로) 같은 판으로 본다 |
| 키트를 고친 뒤 | `install-check --all <폴더>` — 그 아래 설치마다 ⑨ 판 · ① 동일만 한 표로, 뒤처진 설치가 있으면 exit 1. 키트 저장소 로컬 `.harness/harness.json` `installs.skip` 의 설치는 「제외」 줄 — exit 0 이 키트 개선의 끝 · 그래프 도구 · 훅 · 규칙을 고쳤으면 그 앞에 `npm run bench -- --run`(§6.5) |

절차는 SETUP.md 가 정본이다. 설치에 가는 것은 `lib` · `tools` · `policy` · `templates` 뿐이다(`lib/parts.mjs`) — `proof/` 는 키트에 남아 사본을 겨눈다.

## 6. 그래프 상세

### 6.1 저장

`.harness/graph/requests.jsonl` — 한 줄이 기록 하나인 append-only 파일이다. 위치는 `harness.json` `graph.store` 로 바꿀 수 있다(옛 기록을 제자리에서 잇는 설치). 도구는 자기 파일 위치 기준으로 설정(`../harness.json`)과 기본 위치(`../graph/`)를 찾는다 — 훅이 어느 cwd 에서 돌아도 같은 파일을 읽는다. 자동 로드되지 않는다 — 도구와 훅으로만 읽으므로 무한히 쌓여도 세션 비용이 0 이다.

| 필드 | 뜻 | 비고 |
|---|---|---|
| `req` | 사용자 요구 한 줄 — 기록의 이름 | 필수. id 가 없고 다른 기록이 이 문자열로 가리킨다 |
| `terms` | `{"<현업 용어>": "<시스템의 실체>"}` | 키는 사용자의 말, 값은 테이블 · URL · 컬럼 · 서비스 |
| `files` | 실제로 만진 파일 | 줄번호는 떼고 저장한다 |
| `tables` | DB 테이블 | 선택 |
| `note` | 함정 · 기각한 대안 한 줄 | `⏸` 로 시작하면 하다 만 것. 줄바꿈 · 800자 초과는 `graph-append` 가 거부한다(exit 1 · 한 건이라도 거부되면 아무것도 쓰지 않는다) |
| `supersedes` | 이 기록이 무효화하는 이전 `req` — 1개 또는 배열 | 한 글자만 달라도 사슬이 끊긴다 → `--check` 가 잡는다 |
| `date` · `recorded` | 일이 일어난 날 · 적은 날 | 둘 다 오늘이 기본, 소급할 때만 `date` 를 준다 |

```json
{"date":"<YYYY-MM-DD>","recorded":"<YYYY-MM-DD>","req":"<요구 한 줄>","terms":{"<현업 용어>":"<실체>"},"files":["<경로>"],"note":"<함정 한 줄>"}
```

- `req` 머리말: `정본: `(같은 주제의 통합본 — 훅이 1장만 낸다) · `용어 학습: `(`graph-alias` 가 붙인다) · `용어 사전: `
- 저장은 평평한 줄 목록이다. 기록 순서(줄 순서) · 대체됨 · 언제부터 낡았나는 읽을 때 `supersedes` 로 만든다

### 6.2 쓰기

| 언제 | 무엇으로 |
|---|---|
| 대화 중 사용자의 말 → 실체를 알아낸 그 턴 | `graph-alias <말> "<실체>" [--file 경로]… [--note 함정]` — 알아내기 전에는 적지 않는다 |
| 작업 끝 — `graph.md` 3절 | `graph-append` (stdin JSON). 첫째 문 「이 저장소의 지식인가」 — 도구 · 훅 · 하네스 사용법이면 적지 않고 그 판단을 `그래프: 기록 안 함 — <이유>` 한 줄로. 파일 · 테이블이 다 비고 면제 머리말(`정본` · `용어 사전` · `용어 학습` · `공백 채움` · `공백 목록` · `정정` · `원문`)도 `scope:"meta"` 도 없는 기록은 도구가 거부한다(exit 1) |
| 기록이 낡았다 | 전체면 새 기록에 `supersedes` · 같은 주제 2건 이상이면 `정본: ` 1건으로 통합 · 한 대목만이면 그 문장을 직접 고친다 |
| 하다 만 것 | `note` 를 `⏸` 로 시작한다 — 끝내면 `supersedes` 로 무효화 |
| 적은 뒤 | `graph-find --check` exit 0(기록을 고친 뒤에) + 방금 넣은 용어로 조회해 엉뚱한 게 1위가 아닌지 |

⭐ 예시 낱말을 어느 필드에도 넣지 않는다 — 전 필드가 색인된다. ⛔ 개인 식별자 · 비밀값을 적지 않는다. 판단 규칙 전부는 `docs/graph-port.md` §3(규칙 파일의 §4 는 22차에 뺐다).

### 6.3 탐색 — `graph-find`

| 명령 | 답하는 물음 |
|---|---|
| `graph-find <어근…>` | 이 말과 비슷한 과거 요구와 그때의 용어 · 파일 · 함정 |
| `--files <경로조각>` | 이 파일을 만진 요구 (1홉) |
| `--with <경로조각>` | 이 파일을 고치면 같이 움직이는 파일 (2홉 — `⛔항상` · `⭐자주`) |
| `--open` | 하다 만 것(`⏸`) 전부 |
| `--gaps [날짜]` | 그 날짜(없으면 가장 이른 기록 날짜) 뒤 커밋 중 바꾼 파일을 가리키는 살아있는 기록이 하나도 없는 것 — 목록만 내고 기록은 쓰지 않는다. 로컬 전용으로 여럿이 쓸 때 동료 커밋의 빈틈을 본다 |
| `--source <req 앞부분>` | 이 기록을 쓴 대화가 어디인가 · 그때 주고받은 코드 블록 — 세션 기록(`~/.claude/projects/<루트 슬러그>/` · `*/subagents/`, `--transcripts <폴더>` 로 바꿈)에서 req 가 든 도구 호출 중 가장 이른 줄을 찾고, 그 앞 사람 입력부터 거기까지의 답에서 코드 블록을 낸다(6개 · 4,000자). 못 찾으면 이유(폴더 없음 · 보관 기간 · 도구 호출에 없음)를 말하고 exit 0. 기록도 세션 기록도 쓰지 않는다. 훅 · 카드 · 규칙에는 없다 — 사람이 부를 때만(한계는 graph-port.md §4) |
| `--check` | 무결성 — 대체 사슬 4종(「중복 대체」는 줄 번호와 처방 줄을 낸다) · 같은 `req` 두 줄(⚠️ · exit 0 — 병합이 제자리 수정의 옛 줄을 남긴 것) · 없는 경로 · 같은 용어에서 낡은 기록이 1위 · `⏸` 표식 누락 후보 · 1위 독점(살아있는 기록 20건부터 — 기록마다 그 `req` 로 묻되 자기를 뺀 1위의 상위3 점유가 50% 이상이면 ⚠️, exit 0). 앞의 셋이 있으면 exit 1 |
| `--promote [정본문서]` | 자주 나오는 용어 → 정본 문서로 올릴 후보 |
| `--all` | 대체된 기록까지 본다 |

**찾는 법**

1. **질의를 토큰으로** — 한글은 2자 이상 낱말에서 흔한 말(수정 · 추가 · 확인 …)을 빼고, 조사를 뗀 형태 · 띄어쓰기만 다른 형태(2~3어절을 붙인 것) · 3자 이상이면 앞 2자 어근까지 만든다. 식별자는 대문자 약어 2자 이상, 그 밖은 5자 이상
2. **토큰마다 점수** — 처음 맞는 규칙 하나만 친다

   | 규칙 | 점수 |
   |---|---|
   | 용어 키와 같다(공백 무시) · 제목 머리와 같다 — 정확일치 | +3 |
   | 파일 경로에 들어 있다 | +2 |
   | 요구 · 용어 키 · 테이블에 들어 있다 — 용어 값은 식별자 토큰일 때만 본다 | +1 |
   | `note` 에 들어 있다 | +1 |

3. **정렬** — 정확일치가 있는 기록 먼저 → 점수 → 최신. 대체된 기록은 뺀다
4. 문장을 통째로 줘서 0건이면 같은 토크나이저로 쪼개 다시 찾는다
5. **출력** — 카드(점수 · 날짜 · 요구 · `용어 → 실체` · 테이블 · 파일 · ⚠️ 함정) + 같은 용어의 이력(최신순, 낡은 것 표시) + 상위 결과에 자주 나온 파일

### 6.4 훅 — 질문마다 대신 조회 (`graph-hook`)

**켜는 조건** — 살아있는 기록 20건 이상 + `--check` exit 0 + 상위 3 기록 점유 < 50%(`graph-measure` 로 잰다. 질의 집합이 없으면 보고에 「독점 미측정」). 켜기: `policy-apply --local --with graph-hook`(공유는 `--local` 없이).

프롬프트마다 `graph-find` 와 같은 토크나이저 · 채점으로 조회한다. 대체된 기록과 사무 기록(`TODO 갱신`)은 뺀다.

| 판정 | 조건 | 넣는 것 |
|---|---|---|
| 1단 — 확신 | 1위가 정확일치 · 식별자 적중 · 제목에 질문 낱말이 2개 이상 닿는(겹치는 토큰은 하나로) 5점 이상 중 하나. 흔한 한글 낱말(살아 있는 기록의 10% 넘게 · 5건 넘게 걸림)의 정확일치는 확신 · 정렬에 세지 않는다(21차) | 카드 2장(1위가 `정본: ` 이면 1장) — 머리말 두 줄(「지난 작업의 단서」 · 전문은 `graph-find <키>` · 이름만 보이면 되묻지 말고 조회 · 기록으로 답하면 답 끝에 기록 날짜와 「○○까지 볼까요?」), 카드마다 제목 · 핵심 파일 3개(허브 파일 · 저장소에 없는 파일은 뺌) · 「전문: graph-find <키>」. 용어 · 함정 본문은 싣지 않는다(25차) |
| 2단 — 약함 | 1단이 아니고 최고점수 3~4 | 점수 상위 10건 색인(날짜 · 요구 · 용어 키 5개) + 「맞는 게 있으면 `graph-find` 로 판다」 |
| 침묵 | 최고점수 ≤ 2 — 「계속 진행」 같은 발화 | 아무것도 |
| `⏸` | 하다 만 기록이 이 질의에 5점 이상 | 순위와 무관하게 「열린 작업」 줄(제목만)을 붙인다 — 4건 이상이면 질의와 가장 겹치는 3건만 펴고 「나머지 N건 · `--open`」 한 줄 |

숫자는 `tools/graph-hook.mjs` 의 상수이고 근거는 graph-port.md §1 · §5.

### 8.1 플러그인 훅 — superpowers · ponytail

| `SessionStart` | `ponytail-activate.js` | ponytail | 모드를 켠다 — **키트 기본(리뷰 스킬만)에서는 플러그인이 꺼져 있어 돌지 않는다** |

- 키트 기본은 ponytail 플러그인을 사용자 범위에서 끄고 사용자 스킬 `ponytail-review` 만 둔다(SETUP ⑥ · `plugin-plan`) — 위 ponytail 훅 세 줄이 돌지 않아 프롬프트 · 서브에이전트마다 node 를 띄우지 않는다. 지시 파일이 ponytail 모드를 쓰는 프로젝트만 자기 설정에서 플러그인을 켜고, 그 프로젝트에서만 세 줄이 돈다
- ponytail 훅은 제한이 5초다. 프로세스 기동이 느린 PC(보안 프로그램이 새 프로세스마다 검사하는 경우)에서는 가끔 「timed out after 5s」로 결과가 버려진다 — 그 프롬프트의 모드 추적만 빠지고 작업에는 영향이 없다. 키트 훅은 10초 · 30초다

### 8.2 프로젝트가 더한 훅 — 예: 화면 디자인 스킬 게이트

키트 밖의 예다. Impeccable 4.5.0(화면 디자인 스킬)과 그 스킬을 먼저 부르게 하는 게이트를 들인 프로젝트에서는 아래가 §1 · §8.1 에 더해진다.

| 이벤트 | 무엇이 | 하는 일 |
|---|---|---|
| `SessionStart` | `impeccable hook` | 세션을 준비한다 |
| `PreToolUse` (`Write\|Edit\|MultiEdit\|Bash`) | `.claude/hooks/impeccable-gate.mjs` — 그 프로젝트의 파일 | 에이전트마다 처음 화면 파일을 쓸 때, `impeccable` 스킬을 안 불렀으면 막고 작업 설명과 함께 부르게 한다. Impeccable 자기 에이전트(`impeccable-*`)는 통과 |
| `PostToolUse` (`Edit\|Write`) | `impeccable hook` | 화면 파일을 고친 뒤 디자인 검출기(즉시 단계) |
| `Stop` | `impeccable hook` | 응답이 끝날 때 전체 규칙 검사 |

화면 작업 요청 → 모델이 대개 스스로 `impeccable` 을 부른다 → 안 불렀으면 게이트가 첫 화면 파일 쓰기를 막아 부르게 한다 → 새 화면은 Impeccable 흐름(질문 → 방향 → 화면 브리프 → 구현 → 스크린샷 검토) → 고칠 때마다 검출기. 서브에이전트는 사용자에게 물을 수 없어 방향 단계를 건너뛴다 — 새 화면의 방향은 메인 세션에서 정한다.
